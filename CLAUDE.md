# Poker Equity — правила проекта

> Приложение: покерный калькулятор эквити `poker-equity`.
> Требования — только в `SPEC.md`, принятые решения — в `DECISIONS.md`. Читать их в начале работы.
> Источник общих правил: `madess3/android-rules/CLAUDE.md`.

Общие правила для всех личных приложений. Копируются в каждый новый репозиторий приложения
и дополняются файлом `SPEC.md` (ТЗ конкретного приложения).

## 1. Контекст
- Владелец не программист: формулирует видение и проверяет результат на телефоне. Код пишет, собирает и исправляет только Claude.
- Тестовое устройство: Nothing Phone 3a, Nothing OS 5.0, Android 17. Установка через APK из GitHub Releases.
- Цель: личное использование, при хорошем результате выход на широкую аудиторию и порт на iOS.
- Каждое приложение — отдельный приватный репозиторий `madess3/<app-name>`. Доступ есть только у владельца и Claude.

## 2. Общение
- Язык общения русский; ответы структурированные, без воды.
- Объяснять простыми словами, что делает код и зачем, без жаргона.
- Вопросы задавать по одному, до начала работы.
- Перед созданием файлов, артефактов или крупных изменений спрашивать разрешение.
- Не переписывать файл целиком, если нужна точечная правка.

## 4. Экономия токенов
- Читать только нужные файлы, без сканирования всего проекта.
- `SPEC.md` — единственный источник требований. Решения фиксировать в `DECISIONS.md` (дата — решение — причина), чтобы не обсуждать повторно.
- Одна итерация = одна функция или один баг.
- Правки точечные (Edit), без перезаписи файлов.
- Большие объёмы (более 300 строк нового кода за раз) сначала согласовывать планом.
- Сначала делать простое рабочее решение, оптимизировать при реальной необходимости.
- После каждой итерации в `SPEC.md` обновлять раздел «Статус»: что готово, что дальше.

## 5. Стек
- **Flutter** (stable) + **Dart**, Material 3.
- Минимальная версия Android: 8.0 (minSdk 26); target — последняя стабильная.
- Используем только пакеты с поддержкой Android **и** iOS, чтобы порт на iOS был без переписывания.

| Задача | Пакет |
|--------|-------|
| Состояние | `flutter_riverpod` |
| Навигация | `go_router` |
| База данных | `drift` (SQLite) + `sqlcipher_flutter_libs` для шифрования |
| Настройки | `shared_preferences` |
| Секреты (ключи, PIN) | `flutter_secure_storage` |
| Биометрия | `local_auth` |
| Google Drive | `google_sign_in` + `googleapis` (папка `appDataFolder`) |
| Локализация | `flutter_localizations` + `gen-l10n` (ARB-файлы) |
| Камера / распознавание | `camera`, `google_mlkit_*` (по необходимости) |

Новый пакет не из таблицы добавлять только с объяснением, зачем он нужен.

## 6. Структура кода
```
lib/
  main.dart
  app/            # тема, роутер, локализация, настройки
  core/           # общие утилиты, хранилище, бэкап, безопасность
  features/<имя>/ # отдельная функция: data / logic / ui
  l10n/           # app_ru.arb, app_en.arb
test/             # тесты логики (обязательно для расчётов)
```
- Вычисления и бизнес-логика держатся отдельно от UI и покрываются тестами.
- Никаких строк интерфейса в коде, только через локализацию.

## 7. Стандарты интерфейса (по умолчанию)
- **Стиль:** минимализм, Material 3. Цвета и отступы задаются в одном месте (`app/theme.dart`), чтобы потом легко перекрасить.
- **Тема:** светлая, тёмная и системная. Переключатель одной кнопкой в шапке бокового меню, как в Telegram, с плавной анимацией. Выбор сохраняется.
- **Языки:** RU и EN, переключение в настройках; по умолчанию язык системы.
- **Навигация:** боковое меню (Drawer) с пунктами разделов + «Настройки» + «О приложении».
- **Виджеты и уведомления:** решаются в ТЗ каждого приложения.
- Поддержка разных размеров экрана и крупного шрифта; кнопки не меньше 48dp.

## 8. Данные и безопасность
- Данные хранятся локально в зашифрованной БД.
- Синхронизация и бэкап через Google Drive (скрытая папка приложения), опционально в настройках.
- Экспорт и импорт в JSON (полный бэкап) и CSV (таблицы), где это уместно.
- Блокировка входа: PIN и/или биометрия, включается в настройках.
- Ключи API и пароли не хранятся в коде и репозитории. Пользователь вводит их в приложении, они лежат в `flutter_secure_storage`.
- Интернет и AI-интеграции: решаются в ТЗ. Если не нужны, разрешение на интернет в приложение не добавляется.

## 9. Версии, сборка, Git
- **SemVer** `MAJOR.MINOR.PATCH`: MAJOR — крупная переработка, MINOR — новая функция, PATCH — исправление.
- `pubspec.yaml`: `version: X.Y.Z+N`; номер сборки N ставит CI автоматически.
- `CHANGELOG.md`: на русском, понятным языком, по шаблону `templates/CHANGELOG.md`.
- Ветка `main`; коммиты короткие, на английском: `feat: …`, `fix: …`, `docs: …`.
- Релиз: git-тег `vX.Y.Z` → GitHub Actions (`.github/workflows/build-apk.yml`) собирает подписанный APK → GitHub Releases.
- Подпись: у каждого приложения свой keystore, хранится в GitHub Secrets (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`). Без одинаковой подписи обновления не встанут поверх старой версии. Keystore не теряем.
- Перед тегом: `flutter analyze` без ошибок, `flutter test` зелёный.
